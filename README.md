# MSync

![Landing](public/previews/landing.webp)

> A desktop media client that streams and mirrors assets between MMedia and MDrive, with automated folder-based reorganization and bulk watermark/logo stamping at scale

## Spec

## 1. Architectural Core

### 1.1 The Local P2P Mesh Layer (LAN Node Matrix)

- **Decentralized Discovery:** Utilizes **mDNS / ZeroConf** to instantly detect peer active instances of MSync running on the same local subnet without central server configuration.
- **State Synchronization:** Nodes exchange system index parameters continuously via a lightweight gossip protocol, establishing an offline shared network topology map of file hashes, paths, and availability states.

### 1.2 File Organization & Stacking Engine (`spec.json`)

- **Ingestion Isolation:** Automatically monitors targeted local storage drop-folders, extracting technical metadata and EXIF profiles from incoming assets.
- **Atomic Sidecar Stacking:** Parses items against a rule-based organizational design layout. Enforces atomic asset grouping, ensuring raw image files and their matching metadata sidecars (e.g., `.xmp` modification sheets generated by Capture One or Lightroom) are bound together as a single unified entity during sync, clone, or delete operations.

### 1.3 Pre-Flight Processing (GPU/CPU Operations)

- **Local Compute Offloading:** Employs local device hardware acceleration to execute heavy workflow tasks before triggering network transits.
- **Proxy & Utility Generation:** Handles offline bulk watermarking layout rendering and high-speed image preview proxy extraction (extracting lightweight JPEG view-sheets out of large `.CR2`, `.ARW`, or `.NEF` frames) to enable instantaneous offline playback and interface interactions.

### 1.4 Resilient Cloud Uplink Layer & QoS Shaping

- **Transactional State Tracking:** Features an independent background queue manager powered by an integrated local SQLite state library, tracking pause-and-resume statuses for direct-to-cloud multi-threaded uploads into Cloudflare R2/S3.
- **Network Traffic Shaping:** Embeds strict Quality of Service (QoS) rules. Dynamically throttles background upload tasks when a live hardware stream is activated, preserving dedicated uplink bandwidth lanes to ensure streaming stability.

### 1.5 SRT Hardware Streaming Plane

- **Subsystem Interception:** Interfaces with native device video layers (AVFoundation on iOS, Camera2 on Android) or laptop external capture sources (UVC over USB, HDMI capture links).
- **Fail-Safe Frame Buffering:** Broadcasts live video feeds directly to the `MMedia` ingest server via **SRT (Secure Reliable Transport)** to survive network jitter. If connections drop completely, the plane smoothly buffers raw video frames to an append-only local disk cache, automatically backfilling missing frames back to the cloud upon reconnection.

### 1.6 Local Media Conversion Engine

- **Offline Transcoding Pipeline:** Leverages native OS bindings to run embedded FFmpeg binaries or optimized encoding libraries directly on the host chip.
- **Zero-Copy Remuxing:** Detects matching base media tracks to execute container switches instantly (e.g., `.mkv` to `.mp4`) without wasting processing cycles re-encoding matching media streams.
- **Hardware Profile Access:** Dynamically checks and utilizes hardware execution layers based on platform detection: Apple VideoToolbox (`vt`) on macOS, NVIDIA NVENC on Windows/Linux, or Intel QSV.

### 1.7 Wireless Camera Control & Telemetry Layer (CCTL)

- **IP-Based Camera Orchestration:** Establishes a bidirectional control plane over local Wi-Fi or Wi-Fi Direct using TCP/UDP broadcast protocols (integrating native vendor APIs/SDKs like Sony Camera Remote API). Handles instantaneous delivery of exposure, focus, and transport commands.
- **Low-Latency Sub-Stream Decoupling:** Separates the heavy broadcast-quality recording feed from an ultra-low-latency, hardware-accelerated H.264/H.265 monitoring sub-stream. This sub-stream is decoded locally on tablet/mobile clients using zero-copy GPU surfaces.
- **Real-Time DIT Overlays:** Employs local client shaders to render exposure and focus evaluation graphics (Waveform, False Color, Focus Peaking, and real-time 3D LUT conversions) over the live viewport without impacting the camera's internal processing overhead.
- **Granular Focus Assist Matrix:** Exposes explicit hooks into the camera's dual-pixel or phase-detection autofocus arrays. Translates client-side capacitive screen coordinates into immediate spatial focus locks, while exposing raw variable fields for transition acceleration and stickiness.

## 2. Shared Network Topology & Discovery State

When multiple devices initializing MSync connect on a shared network switch or wireless access point, they parse and append their tracking registries into a single shared topology map.

    "node_desktop_01": { "name": "DIT Studio Desktop", "lanIp": "192.168.1.100" },

## 3. Decentralized Mesh Commands (RPC)

### 3.1 The `Clone` Command Loop

Triggered when a local node pulls down missing files from alternative discovered network nodes over the LAN. Enforces a pre-flight storage verification check before spawning QUIC network workers.

```json
{
  "command": "execute_clone",
  "targetDevice": "node_laptop_b",
  "preFlightCheck": {
    "requiredBytes": 45125100,
    "availableBytesOnTargetDrive": 512000000000,
    "allocationStatus": "PASSED"
  },
  "downloadQueue": [
    {
      "fileHash": "sha256_e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "sourceNode": "node_laptop_a",
      "reason": "Peer node shows lower network latency overhead",
      "includeAttachments": ["Garment_Shoot_001.xmp"]
    }
  ]
}
```

### 3.2 The `Dedup` Command Loop

Triggered globally from a centralized high-capacity node to clean up duplicate assets across target mobile or laptop nodes once data preservation is confirmed.

```json
{
  "command": "request_deduplication",
  "initiatorNode": "node_desktop_01",
  "safeVerificationMatrix": [
    {
      "fileHash": "sha256_e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "confirmedStoragePath": "/volumes/raid0/ingest/Garment_Shoot_001.CR2"
    }
  ]
}
```

### 6.2 Camera Configuration Command (Client RPC Outbound)

Triggered whenever a director, DP, or camera assistant updates an exposure parameter, alters autofocus behavior, or triggers a tactile toggle directly on the client tablet interface.

```json
{
  "command": "update_camera_parameters",
  "targetDeviceId": "cam_sony_fx3_098x",
  "initiatorNodeId": "node_tablet_ipad_pro_05",
  "transactionId": "tx_cam_ctrl_88912_a",
  "mutations": {
    "focusConfiguration": {
      "afTransitionSpeed": 6,
      "afSubjectShiftSensitivity": 4
    },
    "exposureSettings": {
      "whiteBalanceKelvin": 4100
    }
  }
}
```

### 6.3 Capacitive Touch-Focus Target Command

Dispatched when an operator touches a specific region of interest on the tablet viewport screen to force a tracking lock or execute a smooth focus pull to a specific target subject.

```json
{
  "command": "trigger_touch_focus_lock",
  "targetDeviceId": "cam_sony_fx3_098x",
  "initiatorNodeId": "node_tablet_ipad_pro_05",
  "normalizedScreenCoordinates": {
    "x": 0.412,
    "y": 0.389,
    "boundingWidth": 0.085,
    "boundingHeight": 0.11
  },
  "trackingMode": "face_eye_priority_override",
  "timeoutFallbackMs": 5000
}
```
